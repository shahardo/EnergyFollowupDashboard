# Energy Followup Dashboard

דאשבורד אינטראקטיבי לתכנון משק האנרגיה בישראל. הוא כולל שני טאבים:

1. **תכנון:** הביקוש וההיצע זה לצד זה. בצד הביקוש: עקומת ביקוש לפי מגזר, וסליידרים לשינוי קצב הצמיחה של כל מגזר. בצד ההיצע: בניית עקומת אספקה ממקורות שונים, כך שתכסה את כל הביקוש; הפער מוצג בגרף. בכל צד בוחרים אחד משלושה תרחישים מוכנים (ראו [תרחישים](#תרחישים)).
2. **מעקב ביצוע:** לוח גאנט שמראה את התקדמות הפרויקטים בכל ערוץ אספקה, מול היעדים.

האפליקציה סטטית ורצה בדפדפן, בלי שרת. תרחישים נשמרים כקבצי JSON מקומיים, דרך "שמור בשם" ו"פתח".

**סטטוס:** שלבים 1–3 מומשו: דף תכנון שבו הביקוש וההיצע זה לצד זה, שלושה תרחישים מוכנים לכל צד, חישוב הפער, התאמה אוטומטית של ההיצע, השוואת תרחישים, מסך מעקב ביצוע, ושמירה ופתיחה של תרחישים. פרטים ב[מסמך האדריכלות](docs/ARCHITECTURE.md) וב-[CLAUDE.md](CLAUDE.md).

## תרחישים

מעל הפרמטרים של כל צד יש תפריט קופץ לבחירת התרחיש. הביקוש וההיצע נבחרים בנפרד, כך שאפשר לבדוק כל צירוף (למשל ביקוש גבוה מול מדיניות מוצהרת).

**תרחישי ביקוש:**

| תרחיש | `preset` | מה הוא מייצג |
|---|---|---|
| ביקוש נמוך | `low` | צמיחה מתונה בכל המגזרים, חשמול ודאטה-סנטרים איטיים, והתייעלות וחיסכון של 10% כל אחד. |
| ביקוש בינוני | `medium` | המשך המגמות הנוכחיות; התייעלות וחיסכון של 7%. ברירת המחדל. |
| ביקוש גבוה | `high` | חשמול מהיר של התחבורה והתעשייה וצמיחה חזקה של דאטה-סנטרים; התייעלות וחיסכון של 3% בלבד. |

**תרחישי היצע:**

| תרחיש | `preset` | מה הוא מייצג |
|---|---|---|
| תרחיש ייחוס | `reference` | **המשך עסקים כרגיל:** הגז ממשיך לגדול (18 GW ב-2050), הפחם יוצא ב-2030, ומתחדשות ואגירה גדלות לאט (25 GW סולארי, 6 GW אגירה). |
| מדיניות מוצהרת | `declared` | היעדים שהממשלה הצהירה עליהם: הפחם יוצא ב-2028, 40 GW סולארי ו-15 GW אגירה ב-2050, הגז נשאר כ-14 GW. ברירת המחדל. |
| מדיניות נבחנת | `tested` | **אפס פליטות נטו (Net Zero):** הפחם יוצא ב-2026, הגז יורד ל-4 GW לגיבוי בלבד, 75 GW סולארי, 35 GW אגירה, 6 GW רוח, גיאותרמיה עמוקה, ויבוא חשמל, מימן ודלקים נקיים. |

כל אחד משישת התרחישים שומר את השינויים שעשיתם בו: אפשר לעבור לתרחיש אחר ולחזור, והסליידרים יהיו כמו שהשארתם אותם (גם אחרי רענון הדף). אמצע כל סליידר הוא הערך של התרחיש הנבחר. "איפוס" בחלון ⚙ מחזיר לערכי הדוגמה רק את התרחיש הנבחר.

כל הערכים הם **ערכי דוגמה** להמחשה, לא תחזית רשמית.

## נתוני המקור לגרפים

כל מה שמוצג בגרפים מחושב בדפדפן משלושה קובצי JSON: **ביקוש**, **היצע** ו**פרויקטים**. אין מסד נתונים ואין שרת.

### איפה הנתונים נמצאים

יש שתי דרכים לשנות את הנתונים:

1. **קובצי תרחיש שנשמרים ונפתחים מהאפליקציה (בלי לבנות מחדש).** בחלון ⚙ (שמירה, פתיחה ופעולות) שומרים תרחיש לקובץ במחשב, עורכים אותו בכל עורך טקסט, ופותחים אותו שוב דרך "פתח קובץ תרחיש…" או בגרירה לחלון. זו הדרך המומלצת: כל המבנה כבר נמצא בקובץ, ורק משנים ערכים.
2. **תרחישי הבסיס בקוד (משפיעים על כל המשתמשים).** אלה הערכים שהאפליקציה נטענת איתם בפעם הראשונה, ושאליהם "איפוס לבסיס" מחזיר:

| קובץ | מה הוא קובע |
|---|---|
| `src/data/scenarios/demand-low.json`, `demand-medium.json`, `demand-high.json` | שלושת תרחישי הביקוש: המגזרים, קצבי הצמיחה, וההתייעלות והחיסכון |
| `src/data/scenarios/supply-reference.json`, `supply-declared.json`, `supply-tested.json` | שלושת תרחישי ההיצע: מקורות האספקה, ההספקים לאורך השנים וסדר ההשלמה האוטומטית |
| `src/data/baseline-projects.json` | הפרויקטים במסך המעקב |

כל קובץ תרחיש הוא קובץ רגיל באותו פורמט ששומרים מהאפליקציה (ראו בהמשך), עם השדה `preset` שמזהה לאיזה תרחיש הוא שייך. רשימת המגזרים של "ביקוש בינוני" ורשימת המקורות של "מדיניות מוצהרת" הן הרשימות המלאות: מגזר או מקור שנוסף רק שם יתווסף גם לתרחישים שמורים ישנים.

אחרי עריכה של קובץ בסיס צריך לבנות מחדש (`npm run build`, או לרענן את `npm run dev`). הקבצים נבדקים כשהאפליקציה נטענת: קובץ בסיס לא תקין ימנע ממנה לעלות. לכן אחרי כל עריכה מריצים `npm test`, שנכשל עם הודעה שמציינת את השדה הבעייתי.

**שימו לב:** הדפדפן שומר את המצב האחרון (ב-localStorage). משתמש שכבר עבד עם הדאשבורד ימשיך לראות את הערכים שלו גם אחרי שינוי בקובצי הבסיס. כדי לראות את הערכים החדשים: בוחרים את התרחיש בתפריט, ואז ⚙ ← "איפוס הביקוש לבסיס" או "איפוס ההיצע לבסיס" (מאפס רק את התרחיש הנבחר). מגזר או מקור **חדש** שנוסף לבסיס מתווסף אוטומטית גם לתרחישים שמורים, בערכי הבסיס שלו.

### המעטפת של כל קובץ

</div>

```json
{
  "schema": "energy-dashboard/v1",
  "kind": "demand",
  "savedAt": "2026-11-04T00:00:00.000Z",
  "data": { "...": "התוכן עצמו, לפי הסוג" }
}
```

<div dir="rtl">

- `schema`: תמיד `"energy-dashboard/v1"`.
- `kind`: `"demand"`, `"supply"` או `"projects"`. לפיו האפליקציה יודעת לאן לטעון את הקובץ, ולכן אפשר לפתוח כל אחד מהשלושה מאותו כפתור.
- `savedAt`: תאריך השמירה (מידע בלבד).
- סיומת שם הקובץ: `*.demand.json`, `*.supply.json`, `*.projects.json` (לנוחות; האפליקציה מסתמכת על `kind`).

### קובץ ביקוש (`kind: "demand"`)

</div>

```json
{
  "id": "preset-demand-medium",
  "name": "ביקוש בינוני (ערכי דוגמה)",
  "preset": "medium",
  "baseYear": 2025,
  "horizonYear": 2050,
  "measures": { "efficiencyPct": 7, "savingPct": 7 },
  "sectors": [
    { "key": "residential", "label": "ביתי", "baseTWh": 22, "growthPct": 2, "curve": "exp", "efficiencyPct": 0.5, "loadFactor": 0.5 },
    { "key": "transport", "label": "תחבורה (חשמול)", "baseTWh": 1, "growthPct": 15, "curve": "s", "sMidYear": 2035, "efficiencyPct": 0, "loadFactor": 0.45 }
  ]
}
```

<div dir="rtl">

| שדה | משמעות |
|---|---|
| `id`, `name` | מזהה ושם התרחיש. השם מוצג בחלון הפעולות ומשמש כשם הקובץ בשמירה. |
| `preset` | **רשות:** `"low"`, `"medium"` או `"high"`. לאיזה תרחיש ביקוש הקובץ שייך. קובץ שנפתח נטען לתרחיש הזה ובוחר בו; בלי השדה הוא נטען לתרחיש שנבחר כרגע. |
| `baseYear`, `horizonYear` | שנת הבסיס ושנת האופק. הגרפים מציגים כל שנה ביניהן. `horizonYear` חייבת להיות אחרי `baseYear`. |
| `measures` | **רשות.** ההתייעלות (`efficiencyPct`) והחיסכון (`savingPct`) באחוזים, 0 עד 40, שמושגים בשנת האופק. ההפחתה גדלה בהדרגה משנת הבסיס, ושני האחוזים מוכפלים: 7% ו-7% הם הפחתה של כ-13.5%. בגרף ההיצע הם מוצגים כפס מקווקו מעל קו הביקוש נטו. |
| `sectors` | רשימת המגזרים. הסדר כאן הוא סדר השכבות בגרף ובפאנל. |

שדות של כל מגזר:

| שדה | משמעות |
|---|---|
| `key` | מזהה קבוע וייחודי באנגלית (למשל `"residential"`). קובע גם את הצבע בגרף. |
| `label` | השם שמוצג בעברית. |
| `baseTWh` | הצריכה בשנת הבסיס, ב-TWh לשנה. |
| `growthPct` | קצב הצמיחה השנתי באחוזים. זה הערך שהסליידר של המגזר משנה, והערך בקובץ הבסיס הוא אמצע הסליידר. |
| `curve` | צורת העקומה: `"linear"` (תוספת קבועה של `growthPct` מערך הבסיס בכל שנה), `"exp"` (ריבית דריבית), או `"s"` (עקומת S: מתחילה לאט, מאיצה ומתמתנת, ומגיעה בשנת האופק לאותו ערך כמו `exp`). |
| `sMidYear` | **רשות, רק ל-`"s"`.** השנה שבה הצמיחה הכי מהירה. ברירת מחדל: אמצע התקופה. |
| `efficiencyPct` | התייעלות פנימית של המגזר, באחוזים לשנה (0 עד 100), מצטברת. נפרדת מ-`measures`. |
| `loadFactor` | מקדם העומס, בין 0 (לא כולל) ל-1. ממנו מחושב ביקוש השיא: `GW = TWh / (8.76 × loadFactor)`. ככל שהמקדם נמוך יותר, השיא גבוה יותר. |

ביקוש השיא הכולל הוא סכום השיאים של כל המגזרים (הנחה שמרנית שכל השיאים חופפים).

### קובץ היצע (`kind: "supply"`)

</div>

```json
{
  "id": "preset-supply-declared",
  "name": "מדיניות מוצהרת (ערכי דוגמה)",
  "preset": "declared",
  "fillPriority": ["solar", "storage", "wind", "gas", "importElectricity", "other"],
  "sources": [
    { "key": "solar", "label": "סולארי (שדות וגגות)", "enabled": true, "renewable": true,
      "capacityGW": [{ "year": 2025, "gw": 6 }, { "year": 2030, "gw": 15 }, { "year": 2050, "gw": 40 }],
      "capacityFactor": 0.19, "capacityCredit": 0.05 },
    { "key": "coal", "label": "פחם", "enabled": true, "renewable": false,
      "capacityGW": [{ "year": 2025, "gw": 4.8 }],
      "capacityFactor": 0.25, "capacityCredit": 0.9, "retireYear": 2028 }
  ]
}
```

<div dir="rtl">

| שדה | משמעות |
|---|---|
| `id`, `name` | מזהה ושם התרחיש. |
| `preset` | **רשות:** `"reference"` (ייחוס), `"declared"` (מדיניות מוצהרת) או `"tested"` (מדיניות נבחנת). לאיזה תרחיש היצע הקובץ שייך. קובץ שנפתח נטען לתרחיש הזה ובוחר בו; בלי השדה הוא נטען לתרחיש שנבחר כרגע. |
| `demandScenarioRef` | **רשות.** שם תרחיש הביקוש שההיצע נבנה בשבילו. אם הוא שונה מהשם של תרחיש הביקוש הפתוח, הדאשבורד מציג אזהרה. |
| `fillPriority` | רשימת `key` של המקורות שמשתתפים בהשלמת פער ב"התאמה אוטומטית", לפי הסדר: הראשון מקבל את כל התוספת עד התקרה שלו, ואז עוברים לבא. מקור שלא מופיע כאן לא מקבל תוספת. |
| `sources` | רשימת המקורות. הסדר כאן הוא סדר השכבות בגרף ובפאנל. |

שדות של כל מקור:

| שדה | משמעות |
|---|---|
| `key` | מזהה קבוע וייחודי באנגלית. קובע את הצבע, ומסך המעקב משתמש בו כ"ערוץ" של פרויקטים. |
| `label` | השם שמוצג בעברית. |
| `enabled` | `true` או `false`. מקור כבוי לא נספר בגרף ובחישוב, אבל נשאר ברשימה עם תיבת סימון. |
| `renewable` | `true` אם המקור נספר ב"מתחדשות מהייצור". |
| `capacityGW` | ההספק המותקן לאורך השנים, כרשימת נקודות `{ "year", "gw" }`. בין נקודות ההספק עולה או יורד בקו ישר; לפני הנקודה הראשונה ואחרי האחרונה הוא נשאר קבוע. צריך לפחות נקודה אחת. הסליידר של המקור משנה את ההספק בשנת האופק. |
| `capacityFactor` | מקדם הניצולת, 0 עד 1: חלק השעות בשנה שבהן המקור מייצר בהספק מלא. האנרגיה בשנה: `TWh = GW × capacityFactor × 8.76`. אגירה מקבלת 0, כי היא לא מייצרת אנרגיה חדשה. |
| `capacityCredit` | תרומה לשיא, 0 עד 1: איזה חלק מההספק זמין בשעת השיא. ההספק המובטח: `GW × capacityCredit`. בתצוגת GW, זה מה שמוצג בגרף ההיצע. |
| `retireYear` | **רשות.** השנה שבה המקור יוצא משימוש. מאותה שנה ההספק שלו הוא 0. |
| `maxGW` | **רשות.** תקרה להספק שההתאמה האוטומטית יכולה להגיע אליו. בלי השדה אין תקרה. |

### קובץ פרויקטים (`kind: "projects"`)

</div>

```json
{
  "id": "baseline-projects",
  "name": "פרויקטים לדוגמה",
  "asOf": "2026-11-04",
  "projects": [
    {
      "id": "p01", "name": "שדה סולארי נגב א'", "channel": "solar", "owner": "יזם פרטי", "mw": 300,
      "plannedStart": "2025-03-01", "plannedEnd": "2027-06-30", "progressPct": 70,
      "milestones": [{ "name": "היתר בנייה", "date": "2025-06-01", "done": true }]
    }
  ]
}
```

<div dir="rtl">

| שדה | משמעות |
|---|---|
| `asOf` | התאריך שהנתונים נכונים אליו (`YYYY-MM-DD`). ממנו נקבע קו ה"היום" בגאנט והסטטוס המחושב. |
| `id`, `name` | מזהה ייחודי ושם הפרויקט. |
| `channel` | ה-`key` של מקור האספקה שהפרויקט שייך אליו (למשל `"solar"`). כך הפרויקט נספר מול היעד של אותו מקור. |
| `owner` | הגורם האחראי (לסינון). |
| `mw` | ההספק שהפרויקט מוסיף, ב-**MW** (לא GW). |
| `plannedStart`, `plannedEnd` | תאריכי ההתחלה והסיום המתוכננים (`YYYY-MM-DD`). הסיום לא יכול להיות לפני ההתחלה. |
| `progressPct` | אחוז ההתקדמות, 0 עד 100. |
| `status` | **רשות:** `"on-track"`, `"at-risk"` או `"delayed"`. אם חסר, הסטטוס מחושב מההתקדמות מול הזמן שעבר. |
| `milestones` | אבני דרך: `{ "name", "date", "done" }`. אפשר רשימה ריקה `[]`. |
| `notes` | **רשות.** הערות חופשיות. |

### הוספת מגזר או מקור חדש

1. מוסיפים רשומה לרשימה `sectors` או `sources`, עם `key` חדש וייחודי באנגלית וכל שדות החובה שבטבלאות.
2. כדי שיהיה לו צבע קבוע, מוסיפים את ה-`key` עם צבע ב-`src/components/charts/palette.ts` (`sectorColors` או `sourceColors`). בלי זה הוא יקבל צבע ברירת מחדל.
3. במקור חדש: אם הוא אמור להשתתף בהתאמה האוטומטית, מוסיפים את ה-`key` שלו ל-`fillPriority` (או מסמנים אותו בפאנל ההתאמה האוטומטית).
4. בקובץ בסיס: בונים מחדש ומריצים `npm test`. בקובץ תרחיש: פותחים אותו באפליקציה.

### כשקובץ לא נפתח

האפליקציה בודקת כל קובץ לפני הטעינה. קובץ לא תקין לא נטען, והתרחיש הפתוח לא משתנה. הסיבות הנפוצות:

- JSON לא תקין: פסיק מיותר אחרי האיבר האחרון, מירכאות חסרות, או מירכאות "חכמות" שמעבד תמלילים הכניס.
- שדה חובה חסר, או מספר שנכתב כטקסט (`"2"` במקום `2`).
- ערך מחוץ לטווח: `capacityFactor` או `capacityCredit` מעל 1, `loadFactor` 0, `measures` מעל 40, או תאריך שלא בפורמט `YYYY-MM-DD`.
- `schema` או `kind` שגויים במעטפת.

כל הכללים מוגדרים במקום אחד, ב-`src/schema/index.ts`.
